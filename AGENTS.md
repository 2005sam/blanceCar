# AGENTS

## Project Overview

- **MCU**: STM32F103C8T6
- **RTOS**: FreeRTOS (currently not used, will be added in future versions)
- **HAL**: STM32 HAL library (in `Drivers` folder)
- **Language**: C, environment: STM32CubeIDE

## Directory Structure

- **BSP** – Board Support Package (hardware abstraction for battery, motors, sensors). **Only folder AI may modify.**
- **Application** – Main balance car logic (sensor processing, motor control, UI).
- **Algorithm** – Control algorithms (PID, Kalman filter, etc.).
- **Common** – Shared utilities, `error_codes.h`, `settings.h`.
- **OSAL** – OS abstraction layer (placeholder, not used yet).
- **Core** – Low-level STM32 core files (startup, system clock, etc.) – **generated by CubeMX, DO NOT MODIFY.**
- **Drivers** – STM32 HAL drivers (ADC, timers, GPIO) – **generated by CubeMX, DO NOT MODIFY.**
- **tests** – Reserved for manual testing only; AI must not create or modify test files.

**Dependencies**:
Application → BSP → Drivers
Application → Common, Algorithm, OSAL (OSAL unused)

## Code Style

Follow **Google C style guide** with embedded adaptations:

- **Functions**: `CamelCase` (e.g., `Bsp_Init`, `Motor_SetSpeed`)
- **Variables**: `snake_case` (e.g., `motor_speed`, `battery_voltage`)
- **Types (structs, enums, typedefs)**: `PascalCase` (e.g., `MotorController`)
- **Macros & constants**: `UPPER_SNAKE_CASE` (e.g., `#define MAX_PWM 1000`)
- **Indentation**: 2 spaces, no tabs
- **Const**: Use `const` whenever possible
- **Comments**: `//` for single-line, `/* */` for multi-line. `// TODO(username): description`

### Return Codes (defined in `Common/error_codes.h`)

All functions **must** return an integer error code constructed with the `MAKE_RETURN_CODE` macro.

**First, add `MODULE_BSP` to the `ModuleID` enum** in `error_codes.h` (e.g., `MODULE_BSP = 0x07`).  
Then, use these helper macros (add them to `error_codes.h` for convenience):

```c
#define RET_OK  MAKE_RETURN_CODE(RETURN_SUCCESS, 0, 0, 0, 0)

#define RET_BSP_INVALID_PARAM   MAKE_RETURN_CODE(RETURN_ERROR, ERROR_LEVEL_MINOR, MODULE_BSP, ERR_TYPE_INVALID_PARAM, 0)
#define RET_BSP_TIMEOUT         MAKE_RETURN_CODE(RETURN_ERROR, ERROR_LEVEL_MEDIUM, MODULE_BSP, ERR_TYPE_TIMEOUT, 0)
#define RET_BSP_HARDWARE        MAKE_RETURN_CODE(RETURN_ERROR, ERROR_LEVEL_MAJOR, MODULE_BSP, ERR_TYPE_HARDWARE, 0)
#define RET_BSP_BUSY            MAKE_RETURN_CODE(RETURN_ERROR, ERROR_LEVEL_MINOR, MODULE_BSP, ERR_TYPE_BUSY, 0)
If these helpers are missing, construct manually:

c
return MAKE_RETURN_CODE(RETURN_ERROR, ERROR_LEVEL_MINOR, MODULE_BSP, ERR_TYPE_INVALID_PARAM, 0);
Example function:

c
int Bsp_Motor_SetSpeed(int speed) {
    if (speed < -100 || speed > 100) {
        return RET_BSP_INVALID_PARAM;
    }
    // ... hardware control ...
    return RET_OK;
}
Security & Boundaries
Modify only: BSP/ folder,docs/ folder, and README.md.

Do not touch: Core/, Drivers/, Application/, Algorithm/, OSAL/, tests/.

FreeRTOS: Do not use any FreeRTOS APIs (tasks, queues, semaphores) – not yet integrated.

Thread safety: Not required (single-threaded execution from main.c).

Workflow
Testing: Do not write unit tests. User tests manually via main.c.

Documentation: After BSP changes, update ARCHITECTURE.md and README.md if interfaces or modules changed.

Driver changes: If you need changes in Core/ or Drivers/, stop and describe the requirement – user will handle it.

Dependencies & Configuration
BSP depends on Drivers (HAL) and Common (error_codes.h, settings.h).

OSAL is a placeholder – do not call any OSAL functions.
```
